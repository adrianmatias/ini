# objective

Tier 1. Static: it changes when the bet changes. What is true today: `now.md`.

## claim

ini is a repository of knowledge in the shape of a fresh repository. It holds the principles, the
code standard, the lessons, the skills and the deterministic gates that agent-written projects
earned, laid out as the project they describe. Mental model: a live cookiecutter for AI agents.
Nothing is installed and nothing is linked. A new project starts as a copy of ini. For an ongoing
project, an agent distils ini into it on demand: the harness first, then compliance, written in the
project's own terms. Either way the project owns what it took and keeps no tie back to ini.
Current and future learnings flow back up into ini, so the next distillation carries them.
Knowledge shared between projects usually drifts as copies or couples them as a dependency. ini
chooses deliberate redundancy instead, and an agent keeps it fresh.

## target

1. **Start**: a copy of ini, once the kickoff's mechanical part is done, is green on every gate but
   the kickoff, and `--prove` rejects every witness. The behaviour suite holds this on every change.
2. **Distillation**: by 2026-12-31, two ongoing projects carry a distillate of ini (the knowledge,
   the skills rows, the gates) with their debt held by a ratchet, and one new project has started
   from a copy.
3. **Compounding**: by 2026-12-31, at least one lesson or skill promoted from a project into ini
   reaches another project.
4. **Budget**: the knowledge stays readable in one sitting, held by the harness gate: every skill
   ≤ 150 lines, learnings ≤ 160, and an `AGENTS.md` ≤ 120.

## not

ini is not a package, a framework, an orchestrator, a router, a plugin, a ticket system or a
dependency. It is not bound to one harness or one model vendor: it is plain files an agent reads,
and checks that run from the tree.

## kill

Reframe if, by 2026-12-31, either holds:

- no ongoing project carries ini's gates, because distilling them costs more than it returns;
- bringing ini's later changes into a project costs more than distilling it from scratch.

## steering order

`objective > foundation > domain > code-standard > gates and behaviour tests > implementation`
