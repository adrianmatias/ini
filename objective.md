# objective

Tier 1. Static: it changes when the bet changes. What is true today: `now.md`.

## claim

ini is a repository of knowledge in the shape of a fresh repository: the principles, the code
standard, the lessons, the skills and the deterministic gates that agent-written projects earned,
laid out as the project they describe. Mental model: a live cookiecutter for AI agents. Nothing is
installed. A new project starts as a copy of ini; an ongoing one is permeated on demand: an agent
reads ini and brings in what the project lacks, the harness first, then compliance. Current and
future learnings flow back up into ini, so the next copy or permeation carries them.

## target

1. **Start**: a copy of ini, once the kickoff's mechanical part is done, is green on every gate but
   the kickoff, and `--prove` rejects every witness. The behaviour suite holds this on every change.
2. **Permeation**: by 2026-12-31, two ongoing projects carry ini's harness (`base/`, the skills
   rows, the gates) with their debt held by a ratchet, and one new project has started from a copy.
3. **Compounding**: by 2026-12-31, at least one lesson or skill promoted from a project into ini
   reaches another project.
4. **Budget**: the base stays readable in one sitting — every skill ≤ 150 lines, learnings ≤ 160,
   an `AGENTS.md` ≤ 120 — held by the harness gate.

## not

A package, a framework, an orchestrator, a router, a plugin or a ticket system. ini is not bound
to one harness or one model vendor: it is plain files an agent reads, and checks that run from the
tree.

## kill

Reframe if by 2026-12-31 no ongoing project carries ini's gates because permeating them costs more
than it returns, or a project had to rewrite `base/` to stay green.

## steering order

`objective > foundation > domain > code-standard > gates and behaviour tests > implementation` —
foundation and code standard are the ones ini carries, read in place under `base/`.
